- CORRECTNESS-02 (canonicalization failure): Rejected — `unwrap_or_else(|_| base_dir.clone())` is a reasonable fallback for non-existent base dirs; the path comparison still works for the common case.

## Spec artifact reliability (audited 2026-10-04)

The task lists above are not a reliable record of what shipped. Verified against the
tree on 2026-10-04; none of the following were previously recorded anywhere.

- **Checkbox drift, `2026-03-02-02-prism-comparison-fuzz`:** `tasks.md` leaves 75
  tasks unchecked (Phases 2-5) and the whole Definition of Done unchecked, but
  `tests/harness/fuzzer.rs` (25 KB) and `tests/harness/comparator.rs` (17 KB) are fully
  written and `prism_comparison.rs` carries 11 tests. The code shipped; the list did not.
- **Checkbox drift, `2026-03-02-01-prism-parity-overhaul`:** all tasks and the entire
  Definition of Done are checked, but `src/grpc/tonic_dynamic.rs` was never created
  (Task 4.1 claims it), WS-vs-OpenAPI path conflict detection was never implemented
  (Task 4.3 step 5), and `ServerConfig.ws_paths: Vec<String>` was never added.
- **False Definition of Done:** the same spec's F01 states "All `$ref` types (local,
  file, URL) resolve correctly" and is checked. `RefResolver` rejects `http://` and
  `https://` refs with "URL-based $ref is not supported". URL `$ref` does not exist.
- **README overclaims two features:**
  - `README.md:61` advertises "Multi-value query parameters with `style`/`explode`
    support". Neither `style` nor `explode` is parsed anywhere in `crates/`. Repeated
    query keys are collected into a `Vec` and validated against `items`; OpenAPI
    serialization is not implemented.
  - `README.md:208` states "Uses tonic for standard HTTP/2 transport". `tonic` appears
    in the runtime only as the `Status` error type; the transport is
    `hyper_util::server::conn::auto`. `tonic::transport::Server` is never constructed.
- **Stale count:** `specs/context.md:55` claimed "223 passing tests, 11 ignored".
  **Fixed** — corrected to 747 with a note to recompute rather than trust the line.
- **Untracked lockfile:** `.gitignore` ignored `Cargo.lock` and it was untracked, making
  DEP-001's "Cargo.lock handles this in practice" false for a fresh clone.
  **Fixed** — the workspace ships the `spec-mock` binary, so the lockfile is now tracked.

Resolved in the same pass: the two README overclaims (`style`/`explode`, "uses tonic"), the
router's "radix tree" naming (it is a segment trie — `RouteNode`/`RouteEdge` now), and the
false statements in both drifted specs, which are annotated inline at the point of each claim.

Two items from this audit turned out **not** to be defects on inspection:

- **`ValidationIssue.schema_pointer` mixing bare and `#`-prefixed pointers** is not an
  inconsistency. The bare form (`/minimum`) addresses a keyword inside a JSON Schema; the
  `#` form (`#/requestBody`) addresses the OpenAPI or AsyncAPI document. They are distinct
  pointer spaces sharing one field, now documented on the field itself.
- **`OperationSpec.operation_id` being unread** is not dead code. It is populated state on a
  public struct, reachable by SDK consumers. It is, however, correctly avoided as the key for
  scenario operation references, because `operationId` is optional in OpenAPI.

Root cause worth fixing separately: these lists are hand-maintained and closed
without diffing against the tree. Until something verifies checkboxes against
reality, treat every `Status: Complete` in this file as unverified.

## Pre-existing defects found during stateful-mocking design

Surfaced on 2026-10-04 while designing `2026-10-04-01-stateful-mocking`. Neither was
caused by that work. **Both are now fixed.**

- **Faker-generated `Location` response headers.** `ResponseHeaderSpec` emitted declared
  response headers from `example` or the faker, so a spec declaring `Location` on a
  `201` received a random string — observed emitting the literal `dfn`. A wrong `Location`
  is worse than an absent one, because it looks like a working URL and sends the client to
  a resource that does not exist.
  **Fixed** — a declared `Location` is now rendered from the matched request path
  (`render_location_header`), ignoring both a foreign spec `example` and the faker. An
  undeclared `Location` is still not invented. Three tests in `http_openapi.rs`.
- **No route conflict detection between WS paths and OpenAPI paths.**
  `crates/specmock-runtime/src/http/mod.rs` serves OpenAPI paths through
  `app.fallback(...)` while WS paths are explicit axum routes, so a spec declaring
  `GET /ws` silently lost to the WebSocket handler — the same defect the prism-parity
  spec's Task 4.3 step 5 claimed to fix.
  **Fixed** — `OpenApiRuntime::shadowed_path` reuses the path router to find a declared
  `GET` operation beneath a WebSocket route, and `HttpRuntime::from_config` now fails
  startup naming both paths. Three tests in `e2e_full_stack.rs`, including one asserting
  a non-colliding base path still starts. The same check will guard the reserved
  `/_specmock/` control prefix when that work lands.
